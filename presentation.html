DAY ZERO

면접 전에,
토론으로 태도를 본다

AI 동료와의 채팅 토론으로 인성을 보는 채용 서비스

지원자는 AI 동료 3명과 토론하고, 담당자는 그 행동 근거로 판단한다.

Day Zero

PROBLEM

태도를 볼 도구가 꾸며지거나, 너무 비싸다

꾸민 답,
비싼 관찰.

조기 퇴사 사유 1위는 직무 적합성 불일치(58.9%)다.

“나는 다른 의견을 존중한다.” — 매우 그렇다
  • 지원자는 성실성을 더 높게 답한다 (d=0.45)
  • 유형별 모범답안이 팔린다
  • 토론·합숙 면접은 평가자와 시간이 많이 든다
  • 실제 면접의 실무 수행형은 10.7%

태도를 싸고 공정하게 볼 방법이 없다

담당자는 꾸밀 수 있는 검사와 비싼 관찰 사이에 있다

SOLUTION

AI 동료 3명과 60분 토론하고, 행동 근거를 남긴다

현재 확인됨

실제 토론 화면 일부 (e2e 기록)

1
성향이 다른 AI 동료 3명

고집하고, 말을 아끼고, 반박한다

2
의견이 부딪히는 상황

모든 지원자가 같은 상황을 겪는다

3
행동 근거 리포트

평가 에이전트가 정리하고, 최종 평가는 담당자가 한다

지원자는 면접 전에 토론하고, 담당자는 그 기록으로 판단한다

VALUE

누가 무엇을 얻고, 어떻게 확인하나

제안 · 파일럿 전 가설
누가 얻나

세 사람의 이득

  • 담당자 대화 근거로 면접 대상·질문을 정한다
  • 면접관 의견이 갈릴 때의 행동을 미리 본다
  • 지원자 말이 아니라 행동으로 보여 준다
→
어떻게 확인하나

핵심 지표 2개

  • 근거 정확도 80% 리포트 근거가 실제 대화와 맞는 비율
  • 면접 질문 활용 담당자 3명 중 2명이 리포트로 질문을 만든다

파일럿에서 검증한다

돈을 내는 기업과 경험하는 지원자 모두 이득이 있어야 한다

SERVICE FLOW

채용 건 하나가 다섯 단계로 흘러간다

현재 확인됨

→ 채용 건을 만들 때 시나리오·프롬프트를 복사해 고정한다. 그래서 같은 채용 건의 지원자는 모두 같은 조건을 받는다.

담당자 → 지원자 → 담당자 순서로 한 바퀴

CANDIDATE

네 단계 동안 카드 6장이 상황을 만든다

현재 확인됨
1

키워드
10분 · 물·불·나무·바람 중 하나

2

문제 상황
18분 · 자료가 열린다

3

해결책
18분 · 해결 방향 하나

4

기획안 작성
14분 · 지원자 혼자 6칸

1경쟁 키워드 반론설득/논리력
2다른 안 지지수용/유연성
2고집형 압박경청/존중
3소극형 침묵배려/포용
3지원자 안 반론설득/논리력
4기여 귀속정직/공정
동료는 지원자 대신 행동하지 않는다 — 반응은 지원자 몫이다

RECRUITER

근거를 보고, 담당자가 조정해 확정한다

현재 확인됨

실제 LLM 세션 리포트의 세부 행동 하나 (가상 지원자)

1
수준과 확신도

세부 행동마다 1~5. 근거가 없으면 "기록 없음"

2
판단 이유

왜 그 수준인지 공개된 척도로 설명한다

3
설계된 장면

모든 지원자가 같은 시각에 겪은 장면이다

4
근거 발언 → 담당자 조정

원문을 확인하고, 메모와 함께 수준을 조정한다

다섯 요소 · 세부 행동 3~4개씩 · AI는 참고, 결정은 사람

ARCHITECTURE

필요한 조각만 나누고, 결정은 코드가 한다

누가 말하고 언제 정해지는지는 코드가, 말투만 LLM이 정한다

Docker Compose 서비스 8개 · MCP와 워커는 내부 API로 api를 거쳐 기록한다

평가표가 요구하는 조각(MCP 3개, 큐·워커, 프론트)만 분리했다

AGENTS

토론 중에는 빠르게, 토론 후에는 꼼꼼하게

현재 확인됨

말할 동료는 규칙이 고르고, 평가는 담당자 검토 앞에서 멈춘다

LangGraph StateGraph · 코드 = 결정적 규칙 · LLM = 모델 호출

요소마다 따로 판단해 서로 끌려가지 않는다

MCP

동료는 평가 기준에 손댈 수 없다

현재 확인됨

도구 단위로 권한을 나누려고 MCP 서버를 셋으로 분리했다

FastMCP · Streamable HTTP · 허용 목록과 전용 토큰으로 이중 차단

debate(손) · rag(눈) · assessment(기록자)
